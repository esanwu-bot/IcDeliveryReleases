## 1. 新-1：`datasheet_url` 丢失 —— 根因不是"后处理洗掉"，是查表键错了

### 1.1 复审的猜测与实测

复审推测「重解用的是纯本地 PDF，或后处理把 `basic_info` 洗掉了」。**两条都不是。**

实测（V4 包）：

```
ADC12DJ5200SE      url=''                                   ← 断链
ADS1201U-1_1K      url='https://source.z2data.com/…/ads1201.pdf'
ADS8568EVM-PDK     url=''    device_datasheet_url='…/sbas543c.pdf'
BOOST-DRV8711      url='…/slvu967a.pdf'
BOOSTXL-C2KLED     url=''    device_datasheet_url='…/spruhh9.pdf'
```

两件板卡的链接其实**没丢**，被 `qc/identity_scope.py:219-222` 主动搬到了
`device_datasheet_url`（理由：那份 PDF 讲的是板上器件，不是这块板）——
是渲染层没跟着回退，页面才变成 0 个链接。

真正"丢"的只有 ADC 件，而根因是一行查表：

```python
bi["datasheet_url"] = url_map.get(pdf.name, "")     # 旧代码
```

`url_map` 按 **PDF 文件名**建索引，而本地文件名是 `{请求订货号}__{抓取文件名}`：

| | 文件名 |
|---|---|
| manifest 里记的 | `ADC12DJ5200SEEVM__adc12dj5200se.pdf` |
| 重解析用的 | `ADC12DJ5200SEAAV__adc12dj5200se.pdf` |

前半段（请求号）不同 → 整名比对落空 → `""`。**没有任何报错**，因为
`dict.get()` 的默认值就是空串。

### 1.2 修法

新增 `qc/source_url.py`，把溯源链收成**一处口径**（解析管线与装配管线共用，
避免"解析时填对、装配时又冲掉"）。三级，先可信后兜底：

1. `manifest` —— 抓取时记下的 `final_url`，原始出处。键取 `__` **之后**的
   PDF 本体名，请求号变了也能命中。
2. `mpn_rule` —— TI 固定直链 `lit/ds/symlink/{mpn}.pdf`。**只在 PDF 自带 TI
   文档号时才拼**（没有文档号就不知道是不是 TI 的件，凭料号前缀猜会把别家
   型号指到 ti.com）。拼的是**器件型号** `basic_info.mpn`，不是请求订货号 ——
   `adc12dj5200seaav.pdf` 是不存在的文件。
3. `unknown` —— 老实留空，由校验器拦下，不编一个看起来像的链接。

板卡件不回填 `datasheet_url`（保持 `identity_scope` 的板级语义），改由渲染层
`_source_pdf_url()` 回退取 `device_datasheet_url`：链接保住了，主体也没被说错。

### 1.3 门禁

复审要求"写进 `ACCEPTANCE_SPECS`，非空才准出包"。**比要求的更严一档**：
放进 `check_core()` 而不是型号级 `ACCEPTANCE_SPECS` —— 后者只对登记过的型号生效，
另外四件仍能带着空链接出包。且这条判据**排在板卡豁免之前**，否则被豁免掉的
恰好就是 V4 丢链接的那两件。

```
basic_info.datasheet_url 为空（溯源链断开，不得出包）
```

## 2. 新-2：符号页退化 —— 根因不是 AAV 后缀，是确定性抽取把 `source` 写残了

### 2.1 复审的猜测与实测

复审推测「`requested_mpn` 用了 `ADC12DJ5200SEAAV`，符号页校验判 `pdf_subject_mismatch`」。
**方向对了一半，机制不是这个。** 实测：

```
basic_info.mpn        = 'ADC12DJ5200SE'      ← 器件型号本身是对的
source.subject_mpn    = None  ×144           ← 144 条全是 None
source.package_ball_count = None ×144
metadata.pin_validation   = 缺失
```

`qc/pin_repair.py::bga_pin_validation()` 是 fail-closed 的，它要求每条球位带完整
溯源（`pdf_sha256` / `page_base` / `table` / `row` / `bbox` / `scope` /
`subject_mpn` / `package_ball_count`）。V4 的 `source` 只有两个键：

```json
{"page": 4, "method": "deterministic"}
```

**这是我自己造成的**：V4 为治"pins 64 vs 144"的采样不稳定，新写了
`deterministic_extract.extract_pins()`（走文本层，只数球号），然后用它**覆盖**了
`pin_repair` 逐球带 bbox 的成果。球数对了，溯源没了 —— 校验器正确地拒绝了它，
于是 59,789 B 退化成 1,294 B。

复审的"诚实度没问题、资产可用性倒退"判断准确：**这是严谨机制的胜利，不是 bug 的胜利。**

### 2.2 修法

分工归一，而不是给两边打补丁：

- `apply_deterministic()` 遇到 BGA **主动让路**，记 `skipped: bga_owned_by_pin_repair`；
- 管线在 `identity_scope` **之后**调 `repair_bga_pins()`（校验第一条就是
  "主体是不是已核验器件"，身份没落库时任何 BGA 都会被清零）；
- 装配阶段（`qc/normalize_doc.py`）对已有产物补跑同一步 —— 这就是"不重解析
  也能修"的那条路。

### 2.3 验收

```
symbols.html   1,294 B  →  60,390 B（CRLF）/ 59,789 B（LF 归一）
<circle>       0        →  144
标题           "BGA 球位待核" → "ADC12DJ5200SE 三视图"
```

**最强的一条证据**：把换行归一（CRLF→LF）后，本包符号页与 V3 的 sha256
**完全相同** —— `06ad646684658050a5f5d189…`。不是"大小接近"，是**同一个文件**
（本包用 CRLF 落盘，601 行差 601 字节，哈希口径本来就归一化换行）。

更强的证据是指纹：

| 字段 | V3 | V4 | 1101 |
|---|---|---|---|
| `pins` sha256 | `3695a8e4314677bf…` | `eb2145b82eb596ee…` | **`3695a8e4314677bf…`** |

1101 的球位指纹与 V3 **完全一致** —— 恢复的不是"数量对上"，是**逐球逐字段的同一张表**；
而热阻 / ESD / VCMI 仍保持 V4 的修正值。等于把 V3 的球图和 V4 的正确值合到了一起。

## 3. 新-3：核验覆盖 4/38 —— 补状态，不重跑旧审计

### 3.1 为什么不能重跑 `table_audit`

V4 §5.2 的取舍（宁可不标，也不覆盖已确认的行）技术上成立：旧审计在融合列上
定位不到行，会把确定性抽出的干净 VCMI 三条又标回 `condition_unverified` ——
用坏尺子量好布。

但代价被复审抓住了：**34 条无状态行正是模型抽的那部分**，也正是 §5.1 自曝
"两次运行仍会漂"（`Power Consumption` 4.01 W ↔ 4 W）的那部分。最不稳定的
数据核验最稀薄，是这轮最该修的一处倒挂。

### 3.2 修法：只陈述来源，不主张对错

`qc/deterministic_extract.stamp_model_unverified()`：给电气 / 绝对最大表里
**没有** `verification` 的行盖 `model_unverified`。

它不主张值错，只主张**来源**：这一行不是确定性抽取产出的，是模型产出的。
把"该不该信"交回读者。这比"不表态"诚实，也比"重跑坏审计"安全。

渲染侧 `model_unverified` 命中字面兜底（含 `unverified`），页面自动打 `†`；
说明条文案改成覆盖两类成因（模型抽取 / 条件与列角色未对上），五语同步。

### 3.3 验收

```
ADC12DJ5200SE  电气 22/22 + 绝对最大 15/15   （V4：4/23 + 0/15）
页面 †         35 处 = 33 个行角标 + 2 处说明条文字
               33 = 37 行 - 4 行（VCMI 3 + VID 1 是 audited_deterministic，不该打标）
```

**4 行不打标是设计**：确定性抽出的核心字段不该被自己的标记反咬。

## 8. 给复审的一句话

三个 P0 的根因都不是"重解析引入的随机损伤"，而是**三处代码缺陷**：
查表键取了会变的前缀、确定性抽取抢了溯源抽取的活、审计状态没在落盘前补齐。
修法都是"让唯一权威做唯一的事"，不是加例外。核心数据仍是 V4 那套（复审已核过），
这一版只把丢掉的溯源、球图、披露补回来，并把它们写成了可执行断言 ——
**同样的错不会在下一版悄悄回来**。
