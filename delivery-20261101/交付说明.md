# 1101 交付说明（五型号，2026-11-01）

本包为 V4 复审后的修复版。**详细取证与逐条对照见同目录《1101_修复说明.md》**，
本文只讲包内有什么、边界在哪。

## 一、本版修了什么（三件 P0）

1. **恢复源 PDF 链接**：V4 的主力件 `ADC12DJ5200SE` 因查表键取了会变的请求号前缀
   （`ADC12DJ5200SEAAV` vs manifest 的 `ADC12DJ5200SEEVM`）而丢链接，页面
   `ti.com` 出现 0 次。现按 PDF 本体名 + TI 文档号兜底两级解析，并**写进核心断言**：
   `datasheet_url` 为空直接判失败，不得出包。
2. **恢复符号页 144 球位图**：V4 用新的确定性抽取覆盖了 `pin_repair` 的成果，
   球数对了但 `source` 只剩 `{page, method}`，符号页 fail-closed 退化成
   "BGA 球位待核"占位页（59,789 B → 1,294 B）。现让 BGA 球位只由 `pin_repair`
   负责（它逐球带 `bbox` / `subject_mpn`），符号页恢复 **144 个球**，换行归一后 sha256 与 V3 **完全相同**（`06ad6466…`）。
3. **补齐核验状态**：V4 电气 4/23 + 绝对最大 0/15 带状态，页面 `†` 为 0。
   现对模型抽的行统一盖 `model_unverified`（只陈述**来源**，不主张值错），
   页面 `†` 恢复 35 处。

顺带：`Peak RF Input Power` 移出电气表（只留绝对最大表）、温度补回 `°C`、
manifest 补回逐件闸门列 `gate` / `gate_reasons`。

## 四、语言

三件重解析型号的四语（ja/ko/de/es）由 `translate_i18n.py --scope full` 补齐，
**3/3 型号流程成功**。

但请勿把"3/3"读成段落全覆盖：实测 ko 页 16 个长段中 **5 段仍为英文回退**。
根因不是翻译失败 —— 页面里有三段**由渲染器拼的叙述句**
（"…is supplied in the FCBGA (144) package with 144 pins…"）硬编码英文，
`multi_language` 里没有对应键，翻译流程成功也覆盖不到。要修需给这几段加五语模板，
属独立改动（已登记为待办）。语言完整性状态仍为 `not_checked`，
缺哪个变体由 manifest 的 `missing_html_languages` 列明。

## 五、可复现性怎么验

每个 `<型号>.json` 的 `metadata.core_sha256` 给出四个核心字段的 sha256：

```
pins     3695a8e4314677bf…   (144)
thermal  4dd75f753101dc12…
esd      a594a1e8e76d13f9…
vcmi_vid e9baa1ab6c95c68c…   (4)
```

复跑同一份 PDF 后比这四个值即可。**不一致请拒收并回报**，不要用"本次看着对"验收。

> `pins` 的 `3695a8e4…` 与 V3 相同（V4 是 `eb2145b8…`）：本版恢复的是 V3 那张
> 逐球带溯源的球位表，不是"数量对上的另一张表"。

## 六、边界（照旧）

**打包校验通过不等于工程验收通过。** 本包只装配指定验收根里已生成的物料，
不查数据库、不在打包时重渲染。`release_status` 仍为 `not_approved`。

仍不稳 / 仍缺的部分，见《1101_修复说明.md》§6，摘要：

- 电气表里**模型抽的非核心行**仍不可复现（两次运行 `drift=24`），本版只把来源
  标清楚（`†`），没让它变稳定；
- AC 性能（SNR / SFDR / NSD / IMD3）仍为 0；
- 分类比 V3 粗（`Integrated Circuits (ICs)` / `Data Converters`）；
- 页面未标注数据手册修订号（Rev. C / `SLVSGH5C`）。
