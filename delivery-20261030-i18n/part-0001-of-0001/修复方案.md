## 4. 第三方四项残留：逐项对账，不照搬旧判断

### 4.1 残留1：死词表已接入，但语义门控仍不合格

第三方指出的“定义了没调用、converter泛命中”属于较早源码状态。**当前快照不是这个状态：**

- `json_to_txt.py:923–938` 的 render 已调用 `_board_evidence_blob`、`_has_evidence` 和三套词表。
- 当前分支不再使用 ADC/DAC/converter/reference 的宽内联正则。
- 匹配函数第749–750行仍是 `any(t in blob for t in tokens)`，即子串。
- 证据汇集第743–745行仍无差别加入 `onboard_device_specs.electrical`。

本次内存复现：

| 输入证据 | 当前结果 | 正确语义 |
|---|---|---|
| small form factor | 命中 sma/clock词表 | 不是SMA连接器，必须不命中 |
| AC-coupled input | 命中 led词表 | 不是LED用途，必须不命中 |
| DC-DC converter | 不再命中clock | 该旧问题已收窄，不能报告成仍存在 |
| fCLK | 没有命中clock | 需要符号语义及对象归属，不是只扩大散文词表 |
| SMA analog input only | 命中clock词表 | 模拟SMA口只支持接口建议，不自动证明clock/oscillator |
| 板载ADS8568 Aperture jitter | 命中clock并输出oscillator句 | 器件抖动不证明板卡时钟源/振荡器存在 |

**确定修法：**沿用接入词表的路线，不恢复第二份内联正则；把布尔词命中升级为带 claim 类型与 scope 的证据裁决。

- 拆成 `motor_output`、`led_string`、`signal_connector`、`clock_input`、`clock_source`、`termination` 等能力。
- 短 token 用词边界；大小写/连字符/Ω/ohm做确定性归一；处理否定、未装、可选和条件。
- 从板级指南、连接器表或具板级source的事实取证；板载芯片参数只能生成“器件级注意事项”，不能授予板级接口事实。
- `SMA`不自动授予 oscillator；`jitter`不自动授予 onboard oscillator；50Ω/termination不自动证明这是时钟而非模拟端口。
- 描述性数据可用于提出“核对是否……”的通用建议，但不把它当成已审计硬件事实。
- 无证据时省略受控检查点，或只给明确的通用建议；“最常见故障”“最快损坏方式”等无来源排名/因果断言也应删掉。
- 渲染和验收 import 同一证据分类函数。词表、归一、优先级与scope规则只能有一套事实源。

| 审计范围 | 主表和备份器件表均有事实 | table_audit仅审主electrical/absolute_max | 隔离区事实没被核验 |
| 发布输入 | 当前渲染消费parsed JSON | acceptance重建不生成facts；facts默认写全局data/facts | 侧车未绑定本次batch/输出 |

`BOARD_CONFIRMED`只确认商品身份，不能证明PDF一定是指南，更不能证明表中每行都是整板参数。`board_identity.py:390–403`允许订购号精确匹配即确认板卡；`identity_scope.py:343–352`却由此直接设置`document_scope=board_user_guide`。这是语义越权。

另外，`table_audit.py:1152–1157`靠表标题判board/chip，标题缺失或generic Input Voltage也不等于已确定整板/器件，不能成为唯一裁决。

**确定修法：**本轮先做最小canonical契约及G2验证，不借小补丁无限扩张；P2再迁移完整facts单源发布。

- 商品类型、文档类型、每行对象/归属、引脚归属为四个不同维度。
- 保留兼容字段，但建立唯一权威路径与一致性校验；旧别名只作迁移输入。
- scope标准建议`device|board|onboard_device|subcircuit|unresolved`；完整枚举必须同时被writer、TXT、symbols、audit、delivery消费，不能只在文档定义。
- 各事实具`subject_mpn/subject_kind/source/pdf_sha256/page/table/row/column_roles/condition/verification`；子电路条件不是整板统参。
- 请求型号固定作为文件/页面主键；`ADS1201U-1/1K`与安全名映射存manifest，不用器件别名覆盖请求号。
- 冲突、不洁输入、未知枚举、缺scope均fail-closed：进入待核或说明页，不回退裸芯片/板级表。

## 5. 额外阻断：范围字段“看起来已审计”，实际仍是错误来源

### 5.1 normalize_ranges不应制造PDF列证据

`qc/postprocess_qwen.py:167–201`从原value字符串拆出两端后，同时生成range、columns_raw和columns。对`80 to 100`这类模型输出，它直接赋MIN=80/MAX=100，哪怕PDF真实列是MIN/TYP。

因此：

- 字符串改成`to`是展示改善，不是MIN/MAX真值修复。
- `columns_raw`目前不能一概称“PDF真值”，它也可能来自未审计的模型字符串。
- G0若只要求有columns，就会接受后处理自造columns，构成新的假绿。

**修法：**未审计规范化只写展示候选及`origin=derived_from_value`；不得写PDF列证据。列角色由原表定位/人工签核赋予。已有污染列不能靠“字段已有所以跳过”保留，必须在本五件重核时回收再审。

### 5.2 _range_text实际优先级与第三方描述相反

当前`json_to_txt.py:593–603`先读range，再读columns_raw，再读columns；不是“PDF raw优先”。用冲突fixture（range=0/5、审计raw=0/3.4）调用，得到0 to 5。此fixture仅用于验证优先级，不是ADS1201真实参数。

**修法：**已审计原列优先；range只在来源支持、MIN/MAX确实是范围且没有TYP时使用；MIN/TYP/MAX保持角色标签。遇到冲突产生finding并阻断，不选一个值静默发布；数值0判空使用`is not None`，不能用truthiness。

### 5.3 acceptance_rebuild没有执行完整数值审计

`qc/acceptance_rebuild.py:51–77`执行scan、重复合并、范围规范化、identity_scope和球号修复，**没有调用table_audit.audit_json**。当前manifest共45次range规范化、0条合并，只能证明动作发生，不能证明错值被修。

五件JSON当前没有绑定本轮完整`metadata.audit/metadata.verification`；manifest也没有源码哈希、输出哈希、完整时间、run_id。单独存在旧audit文件不能证明当前产物被审过。
