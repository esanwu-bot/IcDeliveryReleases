## 二、板卡参数归属三态（任务四）

### 问题

`specs.scope` 只能给一个值。`BOOST-DRV8711` 的用户指南里同时有两类参数：

```
Voltage Range                    8.2 to 52 V    External power supply input   ← 整板
Continuous Current per H-Bridge  4.5 A          Max continuous                ← 板载 DRV8711
```

一个值盖不住，页面把两者印在同一张表里，读者会拿 DRV8711 的 4.5 A 当整板能力。
ChatGPT 8.0 复审原话：「绝不能让板载芯片参数漏进整板规格」。

### 做法

新增 `qc/board_scope.py`，四条判据（全部可重放，不看模型怎么说）：

1. **源文档是器件数据手册** → 表里每一行都是 `onboard_device`；
2. **用户指南 + 行名/条件命中整板接口词汇** → `board_level`；
3. **命中片内模块词汇**（H 桥 / 栅极驱动 / 电荷泵 / 步进细分）→ `onboard_device`；
4. **其余** → `unresolved`，不猜。

板级判据**先**过一遍：`Power Input Voltage` 里也有 `voltage`，顺序反了会判错。

### 实测（V5）

| 型号 | 源文档 | `board_level` | `onboard_device` | `unresolved` | 页面 |
|---|---|---|---|---|---|
| `BOOST-DRV8711` | User's Guide | 1 | 1 | 0 | 两张表，各带标题 |
| `BOOSTXL-C2KLED` | User's Guide | 5 | 0 | 0 | 一张表（单桶不印标题） |
| `ADS8568EVM-PDK` | **SBAS543 器件手册** | 0 | 14 | 0 | 一张表 + 段首声明 |

`ADS8568EVM-PDK` 挂的 PDF 是 ADS8568 的器件手册（SBAS543C），整板的电源/连接器规格
**根本不在那份文件里**。判据 1 因此把它全部归为 `onboard_device`，
并在规格段开头明写「整板规格源文档没有」。**不假装有整板参数。**

### 踩到的坑（必须记下来）

第一版把 `board_level` 写进 `row["scope"]`。`scope` 是**合同层已经占用的键**
（`qc/scope_contract.py`），词表只有 `device` / `board` / `onboard_device` / `unresolved`，
而 `canonical_view()` 拿它决定「这一行留主表还是搬隔离桶」。

`normalize_scope("board_level")` 不认识这个词 → 归一成 `unresolved` →
`_row_scope()` 判定与文档 scope 冲突 → **两行全被搬进 `unresolved_specs`**。
`BOOST-DRV8711` 唯一一条真整板参数（`Voltage Range 8.2 to 52 V`）就这样从页面上消失了。
没有报错，没有告警，表只是空了。

改法：键名换成 `attribution`，不碰 `scope`。回归测试 `tests/test_board_scope.py`
锁死这一条（10 例，含「整板参数不能被搬出主表」）。

### 渲染层同时修的一个洞

合同层**只搬** `electrical` / `absolute_max` / `temperature` / `pin_configuration`，
`ac_performance` / `thermal` / `esd` **不在搬运范围**。所以 `ADS8568EVM-PDK` 的
6 条 SNR/SFDR + 6 条热阻 + 2 条 ESD 一直留在主表，读者会把芯片的 ±2000 V
当成整板 ESD 能力。

V5 起渲染层统一走 `_spec_rows()`（主表 + 两个隔离桶）+ `_bucket_groups()`（行级
`attribution`），五个容器（electrical / absolute_max / thermal / esd / ac）同一套口径。
单桶时不印桶标题 —— 芯片页一个字都没变。

## 三、分类粒度上页面（任务二）

`qc/taxonomy.py` 在 V4 已经写好 `basic_info.category_path`，但**页面 0 命中** ——
JSON 里有、页面上看不见，等于没做。

V5 在 `json_to_txt.py` 加面包屑：

```python
_path = [clean(x) for x in (bi.get("category_path") or []) if clean(x)]
if len(_path) < 2:
    _path = [x for x in (clean(bi.get("category")), clean(bi.get("subcategory"))) if x]
```

实测：

| 型号 | 面包屑 |
|---|---|
| `ADC12DJ5200SE` | `Integrated Circuits (ICs) › Data Acquisition › ADCs` |
| `ADS1201U-1/1K` | `Integrated Circuits (ICs) › Data Acquisition › ADCs` |
| `BOOST-DRV8711` | `Boards & Development Tools › Development Boards / Evaluation Boards` |
| `BOOSTXL-C2KLED` | `Evaluation Boards & Kits › Power Management Evaluation Kits` |

`category_path` 缺失时退回 `category › subcategory`，两者都没有就不印 ——
不编造分类。

## 四、韩语本地化：6 段英文模板句清零（任务三）

### 根因

不是翻译失败，是**渲染器拼接句硬编码英文**。技术洞察的 9 组设计检查点、
封装叙述句、4 组 FAQ 问答都写在 Python 里，`STATIC_I18N` 里根本没有这些键。

### 做法

新增 `_SENTENCE_I18N`（五语 22 键）与 `_LIST_JOIN`（连接词按语种）：

| 语种 | 列表连接 |
|---|---|
| `en` | `", "` / `", and "` |
| `ja` | `"、"` / `"、"` |
| `ko` | `", "` / `", "` |
| `de` | `", "` / `" und "` |
| `es` | `", "` / `" y "` |

6 段硬编码英文全部改模板：`is supplied in…` / `uses the … package` /
`The device is specified with…` / 4 组 FAQ 问答。

### 实测

`ADC12DJ5200SE` 渲染后正则提取所有 `>40` 字符的 `<p>`，检测目标语种字符：

| 语种 | 纯英文段落（V4） | 纯英文段落（V5） |
|---|---|---|
| `en` | 0 | 0 |
| `ko` | **6** | **0** |

静态词条回退数 `key_fallbacks = 0`（109 个词条全部命中韩语）。

### 但「覆盖率」不是 100%，如实写出来

`i18n_coverage` 实测 0.9794~0.9837，缺口是 2 个叙述块：

- `technical_insight`（技术洞察正文）—— 生成式，只有英文；
- `faq`（常见问题）—— 生成式，只有英文。

这两块**不是硬编码模板**，是模型生成的内容，要走 `multi_language` 补齐。
它们目前**整段不渲染**（不是渲染成英文），所以页面没有英文残留，但也不算已本地化。
`i18n_complete` 因此是 `false` —— 这是实测结果，不是失败。

## 五、管脚描述豁免（任务三）

### 问题

复核方把 63 个英文 `<li>` 判为「未翻译残留」。

### 判断：不该翻

`pin_configuration` 的描述是管脚功能名（`VDD`, `AGND`, `SDO/SDI`, `No connect`）。
IEEE 器件手册与封装规格里，这类文字按英文原样引用，译成目标语言反而与读者手上的
datasheet 对不上 —— 这是**工程惯例**，不是漏翻。

### 做法

1. `manifest.csv` 新增 `pin_desc_exempt` 列，`true` 表示适用豁免；
2. 渲染层在非英文语种下印一行小字说明（`pin_desc_lang_note`，五语）；
3. 豁免范围**仅限** `pin_configuration`。features / applications / description /
   technical insight / FAQ **不豁免**，仍按实测覆盖率考核。

`ADS8568EVM-PDK` / `BOOST-DRV8711` / `BOOSTXL-C2KLED` 的 `pin_desc_exempt=false`
—— 板卡件没有引脚表，没有可豁免的对象。写 `true` 才是错的。

## 六、`i18n_complete` 改实测口径（任务三）

### V4 的问题

`delivery_bundle.py` 里写死 `"i18n_complete": "not_checked"`。那是个占位符，
不是结论 —— 复核方看到这一列等于没看到。

### V5 的做法

打包器是「只装配已有物料」模式，**不允许在打包时重渲染一遍**来算覆盖率
（那会让清单里的数字与实际交付的 HTML 不是同一次渲染的产物）。

所以由渲染层落盘侧车 `<型号>.i18n.json`，打包器只读：

```json
{
  "schema": "i18n-coverage/v1",
  "languages": {"ko": {"i18n_complete": false,
                       "i18n_coverage": {"keys_used": 109, "key_fallbacks": 0,
                                         "narrative_blocks": 5, "narrative_fallbacks": 2,
                                         "ratio": 0.9837}}},
  "pin_desc_exempt": true
}
```

`manifest.csv` 取**所有语言里最低**的那个比率 —— 只报最好看的数字等于没报。

## 七、`release_state` 收紧（任务五）

### 问题

`facts_verdict=pass` 被读成「参数全对」。它不是。`pass` 只表示
「没有编造出来的数值」—— 一个数只要在同一页出现过就算 pass，
而 180 页的手册里「同页」几乎是必然的。ChatGPT 8.0 复审原话：
「同页命中证明不了归属」。

### 做法

`DATA_VALIDATED` 判据加一条：`data_anchor` 的分子等于分母，
即每一行有数值的工程参数都锚定到**原厂表的具体行**（带 `bbox` + `row_sha256`，
可从 PDF 重放）。达不到就停在 `PACKAGING_PASSED`。

`manifest.csv` 新增 `data_anchor` 列，直接写 `已锚定/总行数`。

### V5 实测

| 型号 | `data_anchor` | `release_state` |
|---|---|---|
| `ADC12DJ5200SE` | 88/108 | `PACKAGING_PASSED` |
| `ADS1201U-1/1K` | 31/50 | `PACKAGING_PASSED` |
| `ADS8568EVM-PDK` | 14/14 | `DATA_VALIDATED`（身份未审核，止步于此） |
| `BOOST-DRV8711` | 0/2 | `PACKAGING_PASSED`（`verdict=partial`） |
| `BOOSTXL-C2KLED` | 0/5 | `PACKAGING_PASSED`（`verdict=partial`） |

**这不是退步，是把原本藏在 `pass` 里的缺口摆到台面上。**
V4 的 `verdict=pass` 覆盖了 `value_on_label_page`（同页命中）这一档，
读者会把它读成「已逐行核对」。V5 不再允许这种读法。

## 九、ADS1201 输入范围专项（ChatGPT 8.0 P0）

### 根因不是「表格太乱」

V4 里 `ADS1201U-1/1K` 的 `facts_audit` 是 **0 verified**，当时归因为表格复杂。
实际根因是一个 `NameError`：

```python
# V4 只写了用法没写定义
_SRC_SPLIT_RE = re.compile(r"[^A-Za-z0-9+±/-]+")   # ← 缺
_SRC_NUM_RE = re.compile(r"[+-]?\d+(?:\.\d+)?")     # ← 缺
```

`fill_row_sources()` 在参数名带括号的型号上抛 `NameError`，而 `normalize()`
那时是**整段 try** —— 一个 NameError 把后面 3 个确定性步骤
（`input_ranges` / `absolute_max_roles` / `row_anchors`）全部跳过了。

修法两条：

1. 补上常量定义；
2. 加 `_step()` 步骤隔离 —— 一个步骤失败只影响自己，并把
   `metadata.normalize.<step>_error` 写进 JSON，不再静默吞掉。

### 实测

`ADS1201U-1/1K` 的 `Absolute Input Voltage Range` / `Differential Input Voltage Range`
重切为 4 条子行，每条带真实 `bbox` 与 `row_sha256`：

| 参数 | 值 | 条件 | bbox | `row_sha256` |
|---|---|---|---|---|
| Absolute Input Voltage Range | 0 to +5 V | — | `[36.7, 115.8, 540.8, 125.8]` | `a0823bd7…` |
| Absolute Input Voltage Range | -10 to +10 V | With VBIAS(1) | `[36.7, 124.8, 540.8, 134.8]` | `b7e26b8f…` |
| Differential Input Voltage Range | -5 to +5 V | — | `[36.7, 133.8, 540.8, 143.8]` | `7a9913bb…` |
| Differential Input Voltage Range | -20 to +20 V | With VBIAS(1) | `[36.7, 142.8, 540.8, 152.8]` | `959ed04e…` |

`0 to +5` 与 `-10 to +10` 的 MIN/MAX 不再互相污染，`With VBIAS(1)` 只挂在
真正带 VBIAS 的那两行。

电气行核验状态：**33 `audited_row_anchored` + 4 `audited_deterministic` +
2 `model_unverified`**（V4 是 0 / 46 same_page / 2 unchecked）。

## 十一、仍然没做（不藏）

1. **SINAD / ENOB / NF 没进 AC 表**。`_AC_SYMBOLS` 是白名单，加符号会连带引入
   未经验收的行；ENOB 8.5 目前只在 Features 里出现。
2. **`technical_insight` / `faq` 只有英文**。这两块是生成式内容，不是模板，
   要走 `multi_language` 补齐；目前整段不渲染，所以页面无英文残留，
   但 `i18n_complete` 因此为 `false`。
3. **ADC 20 行仍是 `value_on_label_page`**。这 20 行锚不到具体表格行
   （多子行拼一个区间、或参数名与原表符号差异过大），已进 `risk_queue.csv`
   的 `human_review` 队列。不猜、不硬凑。
4. **BOOST 两件的 `value_in_pdf`**（1 / 3 行）。板卡件本来就没有器件级参数表，
   这些值散落在正文段落里，无法锚到表格行。`verdict=partial` 如实标注。
