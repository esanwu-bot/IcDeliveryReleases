# 1102 修复说明

> 输入：两份交叉复审（ChatGPT 的 1101 评审 6.5/10、元宝的 1101 背书 + V7 清单）。
> 本版不重跑大模型，全部为代码改动 + 落盘后确定性归一 + 重装配。

## 一、这版最重要的结构性变化：证据上车

1101 被判「不能视为重新核验」，根因不是数据错，是**包内没有原件**：
复核方只能相信 `pdf_sha256_recorded`，无法独立重算、无法逐行对照。

1102 起每个型号目录内附原厂 PDF，manifest 给出三个字段：

| 字段 | 含义 |
|---|---|
| `pdf_included` | 是否随包（本版五件全为 `true`） |
| `pdf_sha256_recorded` | 源 JSON 解析时记录的哈希 |
| `pdf_sha256_packaged` | 包内 PDF 实测哈希（原始字节） |
| `pdf_hash_match` | 两者是否一致；`false` 直接 `gate=BLOCKED` |

PDF 是二进制，按原始字节哈希；文本物料仍按 `sha256(CRLF→LF)`。
两者混用会让「复制后哈希不一致」——其实两边都没错，只是算法不同（本版踩过）。

## 二、发布状态阶梯（新增 `release_state`）

`gate` 只说「有没有硬伤」，`release_state` 说「走到哪一级」。五级只进不退：

| 状态 | 判据 | 自动 |
|---|---|---|
| `PACKAGING_PASSED` | 四件必带物料齐备 + PDF 哈希一致 | 是 |
| `DATA_VALIDATED` | `core_validation=pass` 且事实验收表无 MISMATCH | 是 |
| `IDENTITY_APPROVED` | `identity_state` ∈ {IDENTITY_SUPPORTED, BOARD_CONFIRMED} | 是 |
| `CONTENT_APPROVED` | 人工审核页面与多语言 | **否** |
| `RELEASE_APPROVED` | 人工签核放行 | **否** |

后两级只读 `signoff.json`，代码不代签。本包最高到 `IDENTITY_APPROVED`。

## 三、身份状态升为硬门禁

1101 的 `ADS8568EVM-PDK` 带着 `identity_state=IDENTITY_REVIEW` 落了 `CLEAN`，
复审判为「`CLEAN` 被误读成身份已通过」。根因是 `_gate()` 根本没读身份字段。

现在 `IDENTITY_REVIEW` 一律判 `UNRESOLVED`，理由写 `identity_state=IDENTITY_REVIEW`。
本版该件已从 `CLEAN` 变为 `UNRESOLVED`。

README 同时补了四态语义表，明确 `PATCHED` / `CLEAN` **都不代表参数正确**。

## 四、AC 性能确定性抽取（补齐 SNR / SFDR / NSD / IMD3）

此前页面上这四个符号出现 **0 次**。

为什么不能用 `find_tables().extract()`：这张表的单元格文本会串行 ——
实测 TYP 列 12 个值被并成一格（`50 535|.|539|.|548|.`），
条件列读成 `M 0xa Fx Fim FFum Afu INll - =s c –a 2le v d`（乱序）。

做法是**几何用表格、文本用词**：

1. 列带 = 所有单元格 x 边界的排序并集（本表 9 条边界 = 8 列）。
   用「单元格 (x0,x1) 对」当列会裂出 11 个假列，值全塞进一格。
2. 值按视觉行取（同一 y 带的词），一个视觉行 = 一条测试条件。
3. 符号 / 分组 / 单位这类纵向合并的标签，按单元格纵向传播。
4. 只有「单元格文本是单个数值」才按合并跨度传播 —— TYP 列被 find_tables
   判成一整格却堆了 12 个值，那不是语义合并，按单值传播会把 12 行写成同一个数。

结果：**82 行**（SNR 24 / SFDR 23 / NSD 7 / IMD3 28），覆盖双通道与单通道两种模式，
每条都带 `fIN` / `AIN` / 模式等测试条件。逐条与 p14 原文核对一致。

页面新增「AC performance」子表，表头 `SYMBOL / 条件 / MIN / TYP / MAX / UNIT`
（MIN 等记号不翻译，与读者手上的 datasheet 对得上）。

`ACCEPTANCE_SPECS` 只登记「每个符号至少几条 + 必须带条件 + 必须有单位」，
**不登记具体数值** —— 数值锁进验收表，换一版手册就会全线误报。

## 五、电气行逐行溯源（22/22）

球位侧 144/144 都带 bbox 与页码，电气侧此前 `source` **一条都没有**，客户无法验证任何一行。

新增 `fill_row_sources()`：参数名与它的数值**出现在同一页**时，记 `source.page`
与 `source.quote`（原文片段）。只认同页共现，不做模糊匹配 ——
数值在别的页出现不算（那是另一种归属猜测）。补不上的行保持空，空着比填个猜的页码诚实。

结果：`ADC12DJ5200SE` **22/22**，`ADS1201U-1/1K` 35/37。

## 六、逐行 PDF 事实验收表（新增工具）

`qc/fact_acceptance.py` 把每条参数的值拿回原厂 PDF 回打，输出
`facts_audit.csv` / `facts_audit.json` / `risk_queue.csv`，逐行记录
「值是否在原文、在第几页、是否与参数名同页」。

四级结论，不把回打成功说成参数正确：

| 结论 | 含义 |
|---|---|
| `verified` | 确定性抽取器能逐字复现同一行（最强） |
| `value_on_label_page` | 数值与参数名**同页**出现 |
| `value_in_pdf` | 数值只在别处出现 —— 归属未证 |
| `partial` / `not_found` | 需人工 |

为什么不用「数值在原文出现过」就算通过：180 页手册里随便一个像样的数都能在某处找到，
那几乎等于没查。所以按「是否与参数名同页」分档。

实测：

| 型号 | 结论 | 行数 | verified | 同页 | 别处 | 未找到 |
|---|---|---|---|---|---|---|
| ADC12DJ5200SE | pass | 126 | 17 | 109 | 0 | 0 |
| ADS1201U-1/1K | pass | 48 | 0 | 46 | 0 | 0 |
| ADS8568EVM-PDK | pass | 8 | 8 | 0 | 0 | 0 |
| BOOST-DRV8711 | partial | 2 | 0 | 1 | 1 | 0 |
| BOOSTXL-C2KLED | partial | 5 | 0 | 2 | 3 | 0 |

**五件零 `not_found`** —— 没有检出「原文里根本没有的数」。

`risk_queue.csv` 100 行，每行带明确下一步：
96 行 `promote_to_deterministic`（值已同页找到，具备迁到确定性抽取的条件）、
4 行 `human_review`。

## 七、页面事实一致性

1. **文档类型**：新增 `basic_info.doc_type`，从 URL 路径确定性判定
   （`/lit/ds/` = datasheet、`/lit/ug/` = user guide、`/lit/an/` = application note）。
   实测 `BOOSTXL-C2KLED` 的源文件是 SPRUHH9 **用户指南**，页面此前写
   "manufacturer datasheet" —— 本版改为 "manufacturer user guide"。
2. **修订号上页面**：从页脚确定性抽取。ADC 抽到 `SLVSGH5C (Rev. C), revised APRIL 2025`。
   没有尾字母时**留空不默认成 A** —— `SPRUHH9` 原文就是 `SPRUHH9`，
   写 "Rev. A" 等于替原厂编了个修订级。
3. **`user guide..` 双句点**：模板自带句号又统一 `+ "."`。改为 `_sentence()`，
   已有句末标点（`.` `。` `！` 等）就不重复。
4. **条件占位**：17 处 `Datasheet conditions apply.` 改为破折号 + 一条汇总提示
   （`{n} entries above carry no extracted test condition …`）。
   重复 17 遍既不提供信息，又让人以为「条件已确认无特殊」。

## 八、ADS1201U 链接改回原厂

此前指向 `source.z2data.com`（抓取时的第三方镜像，会失效、可能挂错版本）。

规则：TI 的件 + 身份已确认 + 原文带 TI 文档号 → 用官方直链覆盖镜像链接。
**只覆盖非 ti.com 的链接** —— 板卡的 `/lit/ug/` 是用户指南，
硬改成 `/lit/ds/symlink/` 会指向一个不存在的 datasheet。

拼接用的是 **PDF 本体文件名**，不是订货号：`ADS1201U-1/1K` 拼出来是
`ads1201u-1/1k.pdf`（带斜杠、且手册本体叫 `ads1201.pdf`）。本版实测为
`https://www.ti.com/lit/ds/symlink/ads1201.pdf`。

## 九、空存储温度

`temperature.storage = ""` 会被渲染成空括号。改为显式 `not_specified`：
JSON 里明确「原厂没给这个值」，渲染层 `_is_blank_sentinel()` 认这个哨兵，不印空括号。

## 十、本版未做（如实登记）

1. **amax 列角色确定性抽取（12 条 `column_roles_not_verified`）** —— 未做。
   原因：ADC 的绝对最大表横跨 p8–p9，p8 那张表 `find_tables` 识别不出
   （只返回引脚表），表头 `MIN / MAX / UNIT` 只出现在 p9 续页上。
   跨页拼接列角色的出错风险大于收益。**替代证据**：这 15 行已在
   `facts_audit.csv` 里逐行回打，多数为 `value_on_label_page`（值与参数名同页），
   但「哪个值来自 MIN 列、哪个来自 MAX 列」仍未由代码确认。
2. **韩语 5/16 长段落仍为英文** —— 未做。已定位到具体五句
   （`is supplied in the …` / `body dimensions of …` / `is the option documented …` /
   `The headline specifications are …` / `Use the current … drawing`），
   都是渲染器拼接出来的英文句子，不是 `multi_language` 数据缺失
   （`STATIC_I18N` 五语 key 覆盖完整，实测缺 0 条）。改五语模板需重构拼接逻辑，
   本版时间不够，未做。
3. **AC 只覆盖 SNR / SFDR / NSD / IMD3** —— SINAD / ENOB / NF 未抽。
   复审点名的是前四个，本版按此范围收口；扩大范围会引入新的未核验行。
4. **`value_in_pdf` 仍存在**（BOOST 两块板 4 行）—— 数值在原文但不在参数名所在页，
   归属未证，已进 `risk_queue.csv`。
