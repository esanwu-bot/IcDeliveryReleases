# 1102-V2 修复说明

对照元宝对 V11 的第三次复审（9.6 分）。V2 的边界与 V11 一样：
**不重解 PDF、不动事实层的判据**，只做三件事：

1. 把「AC 行从另一个容器逃逸」这条通道堵死（复审的 P0）；
2. 让被扣下的行**在页面上说出来**（G0 无静默）；
3. 把隔离状态落成**机器可读、可重算**的字段（复审明确要求「不要只写在正文里」）。

> 为什么不是「V11 重出」：V11 已推上发布仓库，目录按约定**只追加不修改**。
> 这一版单独开 `delivery-20261102-V2`。

## 1. 【P0】AC 参数跨容器逃逸：已在两个出口同时拦

**复审原话（V11）**：`onboard_device_specs.electrical` 里还留着
`SNR 91.5` / `THD -94` / `SFDR 92` / `Channel-to-Channel Isolation 120`，
建议「查来源 / 补证据 / 不独立就隔离」。

**结论：这 4 行不独立，已隔离。** 判据不是"看起来像 AC"，
而是**它们没有自己的 `bbox` 与 `row_sha256`** —— 没有独立溯源，
就无法证明它不是从 AC 容器复制过来的。

现在有两道出口都在拦：

| 出口 | 位置 | 行为 |
|---|---|---|
| 数据层 | `qc/ac_quarantine.py::quarantine()` | 把逃逸行**物理搬进** `specs.unresolved_ac_rows`，原字段保留 |
| 渲染层 | `json_to_txt.py::_spec_rows()` → `filter_electrical_rows()` | 万一 JSON 没跑过隔离，渲染时兜底扣下 |

**关键是第二道出口现在会说话**（见下一节）。V11 之前它扣完不出声，
页面少 4 行而读者完全不知道 —— 那比留着脏行更糟。

## 2. 【P1】渲染兜底扣下的行必须披露（G0 无静默）

V11 的披露句只数 `specs.unresolved_ac_rows`。老 JSON 没跑过隔离时这个桶是空的，
于是 `n=0`、整句不出现，**4 条 AC 行被无声抹掉**。

V2 起，`_spec_rows()` 把兜底扣下的行**交回调用方**，渲染层按实际条数输出新词条
`specs_ac_escape_withheld`（en / ja / ko / de / es 五语）。
本轮 ADS8568 页面上可读到：

```
10 AC rows were extracted from the source datasheet but are withheld from this page:
their MIN/TYP/MAX column roles or their provenance could not be validated
(a unit or footnote occupied a value cell, or the row was copied from another
container without its own bbox/row fingerprint). The raw rows are kept in
`specs.unresolved_ac_rows` for manual review. AC performance is therefore empty
here by design, not absent from the datasheet.
```

注意最后一句 —— **「空表是刻意的，不是数据源没有」**。没有这句，
复核方会把空表读成"漏抽"。

## 3. 【复审建议】隔离状态落成机器可读字段

复审要求：`formal_container_integrity="pass"` 与 `ac_data_state="withheld"`
要能被机器读到。V2 把它们写进 `manifest.csv` / `manifest.json`，并且**不是装饰**：

| 列 | 含义 | 边界（重要） |
|---|---|---|
| `formal_container_integrity` | `pass` = 正式容器里没有脏 AC 行、也没有无独立溯源的逃逸行 | **只说容器干净**，不说参数正确，**不等于放行** |
| `ac_data_state` | `withheld` = 数据被主动扣押在 `specs.unresolved_ac_rows` | **只说数据被扣**，不说被扣的数据是错的 |
| `container_state_source` | `metadata` = 源文件自带；`recomputed` = 打包时按同一定义补算 | 后者**本身就是缺口**，不要读成「已隔离」 |
| `container_state_match` | 清单记录值与包内 JSON 重算值是否一致 | `false` 会把 `gate` 打成 `BLOCKED` |

**为什么 `container_state_match` 要能改 `gate`**：清单写着 `pass`、源文件里却躺着
脏行，是比缺字段更糟的错 —— 复核方会照着 `pass` 直接放行。

`qc/bundle_selfcheck.py::_container_state()` 会从**包内 JSON 独立重算**这两个值。
它**刻意不复用**打包器或隔离模块的实现：共用一份实现的话，那份实现错了，
自检会跟着一起错，核对就变成自己给自己签字。

## 5. 这一版**没有**做的事

- **没有重解任何 PDF**。所有 JSON 都是 V11 的产物，只补跑了幂等的隔离步骤。
- **没有放宽任何闸门**。`anchor_gate` 的 3 pass / 2 blocked 与 V11 完全一致。
- **没有把隔离行删掉**。10 行原样保留在 `specs.unresolved_ac_rows`，
  带 `quarantine_reason`，可逐条复核。
- **没有替 AC 段补数**。这需要人工重新定列，不是打包环节能做的。
- **没有申请 `CONTENT_APPROVED` / `RELEASE_APPROVED`**。这两级只认人工 `signoff.json`，
  代码不代签。
