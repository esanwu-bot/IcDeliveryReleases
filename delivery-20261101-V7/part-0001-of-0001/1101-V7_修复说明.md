## 1. P0：`data_anchor` 口径拆分（复审 8.9 分的核心问题）

### 病根

V6 的 `data_anchor` 把三件不同强度的事加在一起算分子：

| 结论 | 当时算不算锚定 | 实际证据强度 |
|---|---|---|
| `verified_row` | 算 | 坐标 + 可重放行指纹（最强） |
| `verified_paragraph` | 算 | 坐标 + 正文条目指纹 |
| `verified` | **算** | 名字+数值可复现，**没有坐标** ← 病根 |

于是 `ADS8568EVM-PDK` 14 行**一条坐标都没有**，清单上却写着 `14/14`，
`release_state` 一路进到 `DATA_VALIDATED`。复审原话：**弱证据冒充强证据**。

### 现在的口径（唯一来源：`qc/fact_acceptance.py`）

```python
GRADE_OF = {"verified_row": "row_anchor",           # 坐标 + 可重放行指纹
            "verified_paragraph": "paragraph_anchor",  # 坐标 + 正文条目指纹
            "verified_value": "coord_no_fingerprint",  # 有坐标，指纹不可重放
            "verified": "container_verified",          # 无坐标
            ...}                                       # 其余一律 weak
REQUIREMENT = {"table": "row_anchor", "prose": "paragraph_anchor"}
```

`manifest.csv` 因此把一列拆成四列 + 一个闸门：

| 列 | 含义 |
|---|---|
| `row_anchor` | 坐标 + 可重放**表格行**指纹 / 总数 |
| `paragraph_anchor` | 坐标 + **正文条目**指纹 / 总数 |
| `container_verified` | 名字+数值可复现但**无坐标** / 总数（永不计入达标） |
| `coord_anchor` | 上面两列 + 有坐标无指纹的行（坐标级合计，只作参考） |
| `anchor_gate` | `pass` / `blocked` —— `DATA_VALIDATED` 只认它 |

> **分母从哪来（V7 补的最大一个洞）**：板卡件的板载器件参数放在
> `specs.onboard_device_specs` 隔离桶里，渲染层会把它并回页面，而 V6 的事实审计
> **只遍历主表**。于是 `ADS8568EVM-PDK` 页面上 11 条绝对最大值 + 24 条板载器件电气行
> 从来没进过分母 —— 那个 `14/14` 是 49 行里的 14 行。
> V7 用 `BUCKETS` + `iter_container_rows()` 把隔离桶纳入遍历，分母补全后
> 该型号如实变成 `21/49`、闸门 `blocked`、`release_state` 退回 `PACKAGING_PASSED`。

`DATA_VALIDATED` 的判据同步改为 `facts["anchor_gate"] == "pass"`，
**不再**由打包器自己拿结论反推（`anchored_all` 已删除）。

### 载体怎么判（不许用结论反推）

`param_kind()` 只读 **JSON 的载体声明**：

* `scope=board` / `subject_kind=board*` → 板卡正文参数（门槛 `paragraph_anchor`）；
* `source.method ∈ {label_value_colocation, page_bullet, ...}` → Features 正文条目；
* `verification.status = audited_paragraph` → 明确来自正文条目；
* 整个容器是**点线排版**（`method=dot_leader_verbatim`，如 ADS1201U 的
  Absolute Maximum Ratings）→ 该容器全部按正文参数要求，因为**PDF 里根本没有表**；
* 其余一律 `table`（门槛 `row_anchor`）—— 宁可错杀。

防自证回路：`qc/fact_status_sync.py` 回写的状态带 `status_source` 标记，
判载体时**忽略**它。否则「同步升级状态」会让下一轮把门槛降低，弱证据自己给自己降要求。

## 2. 热阻 / ESD 终于有了坐标（复审 新-7、新-4）

### 为什么 V4~V6 一直停在容器级

这两张表是**横向两格**：名称一列（`RθJA`）、数值一列（`23.9`）。
PyMuPDF 把它们读成两个独立文本行，`find_tables()` 在这两张表上抽不出行
（`extract_spec_rows` 返回 `name=None`），于是既没有 bbox 也没有行指纹。

另外两个坑（这次一并修掉）：

1. `_page_lines()` 会丢掉 **<6 字符**的行 —— `RθJA`（4 字符）和 `23.9`（4 字符）
   全在垃圾桶里，所以「按正文行找」永远 0 命中。
2. 这两张表在 PDF 里常常「先读完名称列、再读数值列」，**按行序往后找**会把
   数值列的第一个数当成第一条参数的数 —— 那就是错锚。

### 现在的做法：行带锚定（`sha_scheme=band`）

```
名称行：包含参数名的文本行（不设长度阈值）
数值格：同一 y 带（±6 pt）、位于名称右侧、整格只有一个数
坐标  ：两格并集
指纹  ：sha256(f"{page}|{名称格归一化文本}|{数值格归一化文本}")
```

判据仍然是「**唯一**才算」：同一页多处命中、或多页都能命中，直接返回 None（不猜）。

实测（ADC 第 10 页 / ADS8568 第 9 页）：

```
RθJA       p10  bbox=[...]  23.9 °C/W    band
RθJC(top)  p10  bbox=[...]  0.8          band
HBM        p9   bbox=[...]  ±2000        band
CDM        p9   bbox=[...]  ±500         band
```

顺带修好的一处：`_row_shas()` 只读 `source.row_sha256`，而 AC 表是
`{parameter, row_sha256, bbox, page}` 平铺结构 —— 只读 `source` 会让这些行
全部退到容器级（`ADS8568EVM-PDK` 的 6 条 AC 行就是这么丢的）。

## 3. JSON 自述与事实表对齐（复审 新-2）

`qc/fact_status_sync.py`：

| 事实表结论 | JSON `verification.status` |
|---|---|
| `verified_row` | `audited_row_anchored` |
| `verified_paragraph` | `audited_paragraph` |
| `verified_value` | `audited_coord` |

**只升不降，且不洗白出处**：

  下游不必再 join CSV。

同步后 `core_sha256` 会随内容变化，因此**同步之后重算核心指纹**（不是拿旧指纹
给新内容背书）。

## 5. 指纹口径文档化（复审 新-3）

复审按「原样 / 空白折叠 / 小写」三种归一各试一遍，`paragraph_sha256` 9/9 都对不上。
原因不是算法错，而是**少了两步、也少了前缀**：破折号统一 + `page|` 前缀。
README 现在给出计算式与可直接运行的片段：

```python
def para_sha(page: int, line_text: str) -> str:
    t = line_text.translate(str.maketrans({"\u2013":"-","\u2014":"-","\u2212":"-",
                                           "\u2012":"-","\ufe63":"-"}))
    t = " ".join(t.split()).lower()
    return hashlib.sha256(f"{page}|{t}".encode("utf-8")).hexdigest()
```

`facts_audit.csv` 同时增加 `sha_scheme` 列，标明这一行的指纹属于哪一套：

| `sha_scheme` | 计算式 |
|---|---|
| `row` | 抽取器的表格行指纹（page / 表标题 / 左上坐标 / 符号 / min / typ / max / 单位） |
| `band` | `sha256(page|名称格|数值格)`（热阻 / ESD 两格表） |
| `paragraph` | `sha256(page|归一化行文本)` |
