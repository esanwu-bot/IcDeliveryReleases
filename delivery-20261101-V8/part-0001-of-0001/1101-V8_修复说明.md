# 1101-V8 修复说明

对照：`delivery-20261101-V7` 的复审报告（工程质量体系 9.2/10，Not Approved）。
V8 **不做功能扩张**，只做收尾：文档一致性、锚定语义限定、弱证据死守、同步补齐。

## P0-1 交付说明与数据割裂（复审 P0）

**问题**：V7 包根 `交付说明.md` 的标题还是 `delivery-20261101-V6`，正文写着
`ADS8568EVM-PDK 14/14 / DATA_VALIDATED`、仍在讲已废止的 `data_anchor`，
还写着「ADS1201U 停在 PACKAGING_PASSED」。而 manifest 是 `21/49 / PACKAGING_PASSED`
与 `IDENTITY_APPROVED`。复核方先读说明再看清单，两份对不上等于没有说明。

**根因**：`交付说明.md` 是**从验收根复制**的上游手写文档，版本一迭代就落后。
手写文档靠「下次记得改」，就一定会有忘的那一次。

**修法**：
1. `delivery_bundle.render_delivery_note()`：**打包时按本包 manifest + facts_audit
   渲染**，所有数字（审计行数 / row_anchor / paragraph_anchor / weak / anchor_gate /
   release_state）与风险队列计数都来自实测，不含手写值。验收根同名文件不再采信。
2. `qc/bundle_selfcheck.py::_check_delivery_note()`：**硬拦**。逐格比对
   标题版本号、六个数字列、`release_state`，并禁止再出现 `data_anchor`。
   任一项不符 → 自检红 → 不出包。自检报告新增 `delivery_note.consistency` 一项。

## P0-2 `anchor_gate=pass` 的语义被读大

`README.md` 与包内《交付说明.md》各增一张**六级证据层级表**：
坐标定位 → 行/段落指纹 → 列语义核验 → 条件核验 → 身份与范围核验 → 人工签核。
每级写明「证明了什么 / 不证明什么」，并明确：
**`anchor_gate=pass` 只表示「证据载体达到门槛」，不等于参数事实已完全正确。**
BOOST 两件的 `paragraph_anchor` 只说明正文段落对得上，不代表板卡参数的
测试条件、供电配置、适用场景已逐条核过。

页面上的正向提示条同步加限定（五语种）：原文「所有条目已锚定」之后补一句
「锚定证明值绑定到该行，**不**证明列角色（MIN/TYP/MAX）、测试条件、脚注已复核」。

## P1 弱证据：一条都不升级

- `ADS8568EVM-PDK` 保持 `anchor_gate=blocked` / `PACKAGING_PASSED`，
  其余弱证据逐条留在 `risk_queue.csv`。V8 只是把其中 9 条
  **经行带几何锚定**拿到坐标（`row_anchor` 19 → 28），不是放宽门槛：
  新锚的每一行都按 bbox 回读原文核过，标签与数值同格同值。
- `ADS1201U-1/1K` 的 `Differential Input Voltage Range` 因 `missing_cols=min,max`
  主动**降级** `verified_row → verified_value`，因此该型号 `anchor_gate`
  由 `pass` 变 **`blocked`**、`release_state` 退回 `PACKAGING_PASSED`。
  这是刻意的：该行 JSON 的 `2 / -20 / +20` 里，`2` 是脚注「See Note 2」的编号，
  被当成了 MIN。**指纹一致只能证明整行文本对得上，不能证明值落在哪一列。**
  改对之后这行才能回到 `row_anchor`。
- `ADS1201U` 的 `Offset Error` / `Gain Error` 仍为空值（行内无数值），不虚构。
- BOOST 两件的板级 / 板载器件归属仍在页面上分开，未做合并表述。
