> 本文件由 `delivery_bundle.py` 在打包时**按本包的 manifest 与 facts_audit
> 实测数据生成**，不含手写数字。凡是与 `manifest.csv` 冲突的旧版说明一律作废。

## 这是什么

五型号详情页物料与解析 JSON 的**复核候选包**，不是已批准上线的正式版本。

- `release_status` 全部 `not_approved`（本包 `mpn_count=5`）
- `CONTENT_APPROVED` / `RELEASE_APPROVED` 未申请，需人工签核
- `i18n_complete` / `i18n_coverage` 为**实测值**，打包时从侧车重算

**打包校验通过不等于工程验收通过，不应直接上线或用于电路设计。**

> **本包已包含全部原厂 PDF 原件**（`<型号>/<型号>.pdf`），复核方可对照包内
> PDF 逐行复核任意一条参数，不需要外部下载、也不需要相信清单里的哈希。

`paragraph_anchor` = 坐标 + 正文条目指纹（正文参数的门槛）；

`weak`（只有「值在同页/别处出现」）与**只有坐标、没有可重放指纹**
（`coord_anchor` 大于 `row_anchor` 的部分）—— 后者在表里不体现在 `weak` 列，
逐条见 `facts_audit.json::mpns.*.blocked`。

## `anchor_gate=pass` 证明了什么、不证明什么

**这六级是叠加的，上一级不自动蕴含下一级。**

| 层级 | 证明了 | **不**证明 |
|---|---|---|
| 坐标定位 | PDF 上确实有这个位置 | 值是否正确 |
| 行 / 段落指纹 | 参数名与数值绑定到了具体载体 | 列角色、测试条件、脚注是否正确 |
| 列语义核验 | MIN/TYP/MAX 等列角色 | 产品身份是否正确 |
| 条件核验 | 温度、供电、测试条件 | 页面有没有错误归属 |
| 身份与范围核验 | 文档对象、数据主体、产品身份一致 | 内容与语言是否已批准 |
| 人工发布签核 | 责任人已审核 | —— 只有它能进正式发布 |

所以：**`anchor_gate=pass` 只表示「证据载体达到门槛」，不等于参数事实已完全正确。**
BOOST 两件全部是 `paragraph_anchor`，那只说明正文段落对得上，不代表板卡参数的
测试条件、供电配置、适用场景已逐条核过。

## 怎么用这个包核对

1. 打开 `manifest.csv`：每件的 `row_anchor` / `paragraph_anchor` /
   `container_verified` / `coord_anchor` / `anchor_gate` 五个字段，
   **一个字段只表达一个证据等级**，不再用一个数字概括。
2. 打开 `facts_audit.csv`：**逐行**的 PDF 回打结果。带 `bbox` 的行可以按坐标
   翻回原页；带 `sha_input` 的行可以 `sha256(sha_input)` 直接重算出该行指纹。
3. 打开 `risk_queue.csv`：还没解决的行与建议动作。
4. 跑一遍自检：`python qc/bundle_selfcheck.py --out <包根>`（独立实现，
   结论写在本文件同级的 `包校验报告.json::selfcheck`，逐项 `expected/actual/ok`）。

## 发布阶梯

```text
PACKAGING_PASSED → DATA_VALIDATED → IDENTITY_APPROVED → CONTENT_APPROVED → RELEASE_APPROVED
```

- `PACKAGING_PASSED`：必带物料齐备，且随包 PDF 与 `pdf_hash` 一致。
- `DATA_VALIDATED`：`anchor_gate=pass`（**只此一条，且含义见上表**）。
- `IDENTITY_APPROVED`：产品身份与文档主体一致（`subject_match=true`）。
- `CONTENT_APPROVED` / `RELEASE_APPROVED`：人工签核，代码不代签。
