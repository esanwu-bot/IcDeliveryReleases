# 交付说明（delivery-batch20-eval-V2）

> 本文件由 `delivery_bundle.py` 在打包时**按本包的 manifest 与 facts_audit
> 实测数据生成**，不含手写数字。凡是与 `manifest.csv` 冲突的旧版说明一律作废。

## 这是什么

本批 8 型号的详情页物料与解析 JSON 的**复核候选包**，不是已批准上线的正式版本。

- `release_status` 全部 `not_approved`（本包 `mpn_count=8`）
- `CONTENT_APPROVED` / `RELEASE_APPROVED` 未申请，需人工签核
- `i18n_complete` / `i18n_coverage` 为**实测值**，打包时从侧车重算

**打包校验通过不等于工程验收通过，不应直接上线或用于电路设计。**

> **本包已包含全部原厂 PDF 原件**（`<型号>/<型号>.pdf`），复核方可对照包内
> PDF 逐行复核任意一条参数，不需要外部下载、也不需要相信清单里的哈希。
> **复核方请用 raw 源或 commit 固定 URL 取文件，不要用 CDN 缓存路径。**
> 复审方在 V5 / V8 / V10 三轮里都被 CDN 缓存坑过：同一路径反复返回
> `403` / `502`、`pdk.json` 首轮返回 0 字节、同一文件要重试三次才拿到内容。
> 拿到的不是包里的字节时，任何结论都不成立。


## 出厂前 clone 复跑（每次出包必做）

出包后一律按**复核方视角**重跑一遍：从发布仓库**全新 `git clone`** 到独立
目录（不复用打包工作区），再用包内自带的 `qc/bundle_selfcheck.py` 从克隆
出来的文件**独立重算**一遍自检。

这样做的原因很实在：打包工作区里残留的缓存、未提交的改动、以及本机与仓库
之间的口径差异，都会让「我这台机器上是绿的」变成一句没有意义的话。
**只有从仓库克隆出来的那份通过了，这次出包才算通过。**

本轮复跑记录（克隆的 commit + 自检结果）写在**发布仓库根目录的 `README.md`**，
不在本包内 —— 记录只有在包推送之后才可能产生，把它写进包里必然是自证。
复核方请对照该记录。

### 三、清单变更：`CDC6CE040000ADLFR` 被 `CDC6CE025000ADLET` 顶替

批次指令里列的 8 件中包含 `CDC6CE040000ADLFR`。该件在**最终轮**并未产出电气表，
运行日志原文：

```

       PARSE_FAILED: empty_electrical（模型未产出电气表，拒绝落盘以保留旧 JSON）
```

即：解析器**主动拒绝落盘**，以免用空结果覆盖该型号已有的可用 JSON。
它在本轮是失败件，不是 ok 件，因此**不在本包内**。

最终轮真正 ok 的第 8 件是 **`CDC6CE025000ADLET`**（`elec=82`、`pins=4`），
本包用它顶替 `CDC6CE040000ADLFR` 的位置。

**为什么不拿早期轮次的 ok 版本回填 `CDC6CE040000ADLFR`**：`qwen-flash` 的逐件结果
不稳定，同一型号跨轮会 ok↔empty 反复（`CDC6CE025000ADLER` 中间轮 `elec=82`、
最终轮 `empty`；`CDC6CE025000ADLET` 修复前 `empty`、最终轮 `elec=82`）。
把不同轮次的产物拼进同一个包，会让「本包 8 件同源于一次解析」这句话不再成立，
复核方也无法用同一份代码复现。宁可如实少一件、换一件，不做跨轮拼接。

`formal_container_integrity=pass` **只**表示正式容器里没有脏 AC 行、也没有
无独立溯源的逃逸 AC 行 —— 它不表示参数正确，更不等于放行。
`ac_data_state=withheld` 表示该型号的 AC 数据被**主动扣押**在
`specs.unresolved_ac_rows`：页面相应段是空表并已披露原因，原始行完整保留在
JSON 里，复核方可逐条复核，不需要相信任何一句总结。

`状态来源=metadata` 表示这两个值是解析/隔离那一步写进源文件的；
`recomputed` 表示该 JSON 从没跑过 `qc/ac_quarantine.py`，这两个值是打包时按
**同一套定义**补算的 —— 后者本身就是一个缺口，不要读成「已隔离」。
`自洽核对=mismatch` 会直接把 `gate` 打成 `BLOCKED`：清单写着 `pass` 而源文件里
躺着脏行，比缺字段更误导。

列含义：`row_anchor` = 坐标 + 可重放行指纹（表格参数的门槛）；
`paragraph_anchor` = 坐标 + 正文条目指纹（正文参数的门槛）；
`weak` = 只到「值在同页/别处出现」的弱证据，已在 `risk_queue.csv` 逐条登记；
`anchor_gate=blocked` 表示该型号存在未达门槛的行，`release_state` 不得进入
`DATA_VALIDATED`（见下文发布阶梯）。注意 `blocked` 有两种来源：
`weak`（只有「值在同页/别处出现」）与**只有坐标、没有可重放指纹**
（`coord_anchor` 大于 `row_anchor` 的部分）—— 后者在表里不体现在 `weak` 列，
逐条见 `facts_audit.json::mpns.*.blocked`。

`facts_verdict` 与 `anchor_gate` **不是同一件事**，两个一起看才有意义：

| 取值 | 含义 |
|---|---|
| `pass` | 无 MISMATCH（PDF 里查得到、值与交付值对得上），**且**每条都达到该载体的证据等级 |
| `partial_pass` | 无 MISMATCH，但有子项未达锚定门槛 → `anchor_gate=blocked`；缺口条数见 `manifest.csv` 的 `facts_note` |
| `partial` / `fail` / `unchecked` | 存在查不到或对不上的行，逐条在 `risk_queue.csv` |

所以本表里 `facts_verdict=pass` 的行，其 `anchor_gate` **一定是** `pass`；
出现 `blocked` 就一定是 `partial_pass` 或 `partial`，两者不会再互相打架。

## `anchor_gate=pass` 证明了什么、不证明什么

**这六级是叠加的，上一级不自动蕴含下一级。**

| 层级 | 证明了 | **不**证明 |
|---|---|---|
| 坐标定位 | PDF 上确实有这个位置 | 值是否正确 |
| 行 / 段落指纹 | 参数名与数值绑定到了具体载体 | 列角色、测试条件、脚注是否正确 |
| 列语义核验 | MIN/TYP/MAX 等列角色 | 产品身份是否正确 |
| 条件核验 | 温度、供电、测试条件 | 页面有没有错误归属 |
| 身份与范围核验 | 文档对象、数据主体、产品身份一致 | 内容与语言是否已批准 |
| 人工发布签核 | 责任人已审核 | —— 只有它能进正式发布 |

所以：**`anchor_gate=pass` 只表示「证据载体达到门槛」，不等于参数事实已完全正确。**
BOOST 两件全部是 `paragraph_anchor`，那只说明正文段落对得上，不代表板卡参数的
测试条件、供电配置、适用场景已逐条核过。

## 怎么用这个包核对

1. 打开 `manifest.csv`：每件的 `row_anchor` / `paragraph_anchor` /
   `container_verified` / `coord_anchor` / `anchor_gate` 五个字段，
   **一个字段只表达一个证据等级**，不再用一个数字概括。
2. 打开 `facts_audit.csv`：**逐行**的 PDF 回打结果。带 `bbox` 的行可以按坐标
   翻回原页；带 `sha_input` 的行可以 `sha256(sha_input)` 直接重算出该行指纹。
3. 打开 `risk_queue.csv`：还没解决的行与建议动作。
4. 跑一遍自检：`python qc/bundle_selfcheck.py --out <包根>`（独立实现，
   结论写在本文件同级的 `包校验报告.json::selfcheck`，逐项 `expected/actual/ok`）。

## 发布阶梯

```text
PACKAGING_PASSED → DATA_VALIDATED → IDENTITY_APPROVED → CONTENT_APPROVED → RELEASE_APPROVED
```

- `PACKAGING_PASSED`：必带物料齐备，且随包 PDF 与 `pdf_hash` 一致。
- `DATA_VALIDATED`：`anchor_gate=pass`（**只此一条，且含义见上表**）。
- `IDENTITY_APPROVED`：产品身份与文档主体一致（`subject_match=true`）。
- `CONTENT_APPROVED` / `RELEASE_APPROVED`：人工签核，代码不代签。
